Prismelo delivers seven service areas. Each has a dedicated page on the main website with scope, process, deliverables and FAQs.

| Service | Primary output | Typical engagement |
| --- | --- | --- |
| [Penetration Testing](/services/penetration-testing) | Findings register + remediation guidance | Scoped project |
| [Cybersecurity Consulting](/services/cybersecurity-consulting) | Risk map + prioritized roadmap | Assessment or advisory |

## Engagement models

**Advisory** — a defined question, reviewed and answered in writing. Useful before committing to a build or a migration.

**Assurance** — an authorized security assessment with validated findings. The output is evidence, not opinion.

**Build** — design and delivery of software, infrastructure or an AI integration, with documentation and handover.

## How scope is set

For every service the same rule applies: what is included, what is excluded, and what completion looks like are agreed in writing before work starts. The [engagement process](/docs/getting-started/engagement-process) page describes how changes are handled.

## Security work has additional requirements

Penetration testing and security assessment work require explicit written authorization from the system owner, an agreed scope and rules of engagement. See [Assessment scope & authorization](/docs/services/penetration-testing) before requesting a test.

<Callout title="What we do not offer" tone="note">
  Prismelo does not currently sell a public hosting product, does not operate a 24/7 monitoring service, and does not issue security certifications. Related advisory work is available; the distinction is stated on each service page.
</Callout>

## Choosing between services

If you are unsure where to start, describe the problem rather than the service. A short advisory engagement is often the cheapest way to decide whether you need a build, a test, an architecture change — or nothing at all.
